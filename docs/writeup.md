# Building an evidence-first circular research agent

Circular research is a useful test of retrieval-augmented generation because the difficult part is rarely producing fluent prose. The difficult part is finding the applicable provision, preserving its wording, recognizing an amendment, and declining to answer when the loaded documents do not support a conclusion. A confident answer can look persuasive while citing an older document or a neighboring paragraph. This project treats those failures as things to measure, rather than assuming that a citation makes an answer reliable.

The implementation runs locally with Ollama and an explicit LangGraph. Its intended source corpus consists of public RBI and SEBI circulars, but the delivered repository begins with fictional FRA training documents. That separation is intentional: the supplied plan specified a substantial human-verified benchmark, while no official PDFs or verified labels were available. Fictional fixtures let the code be tested immediately without presenting invented regulatory requirements as real ones. They establish software behavior, not the quality of regulatory research.

The ingestion pipeline starts with a manifest. A document has a stable identifier, issuer, title, issue date, official source URL, filename, checksum, and page count. Import validates this metadata before writing output. It rejects paths that escape the source directory and detects a changed source file when a prior checksum exists. The parser retains page numbers and removes repeated text only when it appears in page margins. This distinction matters: an obligation repeated in the body of several pages should not disappear merely because it is frequent.

Chunking follows numbered provisions and heading boundaries. It also keeps chunks within one page, which makes page-level citations easier to inspect. Very long lines are split under a hard character limit, and short provisions remain available instead of being silently dropped. There is a tradeoff: a rule spanning two pages may require multiple retrieved chunks. The evaluation therefore needs multi-section cases, and retrieval reporting includes both any-gold recall and coverage of every gold evidence item. A single retrieved passage is not sufficient proof for a question needing two sources.

The retriever offers three distinct configurations. BM25 handles exact phrases, paragraph numbers, and unusual names. Dense retrieval uses a small BGE embedding model and a FAISS inner-product index over normalized vectors. Reciprocal rank fusion combines their ranked lists without pretending the underlying scores have the same scale. An optional cross-encoder reranks a candidate pool. These components are independently selectable because their contribution must be measured. The dashboard will not call a sparse-only result a hybrid-search result, and no reranker improvement is claimed before an actual ablation is run.

The agent always retrieves once before entering the model-controlled tool loop. This is the plan’s documented retrieve-first fallback: small local models can be inconsistent about making an initial search call. Afterwards the model may search again, read a section, list available documents, or use a calculator. The graph bounds agent rounds and actual tool executions. Tool responses are paired with their requests before finalization, including the last permitted round. Evidence is stored in the current request’s graph state, preventing one question from inheriting another question’s citations.

The calculator does not execute Python. It interprets a small allowlist of abstract syntax tree nodes, supports simple arithmetic and date differences, and rejects imports, attributes, exponentiation, and string operations. Input length, AST size, numeric magnitude, and function arguments are bounded. Those restrictions remain in the baseline experiment. Removing essential safeguards to obtain a more dramatic red-team improvement would make the comparison misleading. Defense level D2 therefore documents validation already present in D0 rather than manufacturing a deliberately unsafe starting point.

Final answers use a structured list of claims. Each claim must include a retrieved chunk identifier and an exact quote of at most twelve words. The verifier normalizes whitespace but does not use fuzzy similarity: changing “must not” to “must” cannot pass as a near match. If verification fails, the graph permits one repair attempt, then refuses. This mechanism checks evidence integrity. It cannot determine whether an arbitrary claim logically follows from the quote. The project reports citation support against gold passages separately and explicitly preserves semantic entailment as an unresolved limitation.

Evaluation is designed to survive interrupted local or notebook sessions. Every completed question is appended to a JSONL checkpoint and flushed to disk. A fingerprint binds the result to its corpus, dataset, prompt, model configuration, and source revision. Resuming with changed inputs fails instead of silently combining incomparable runs. Results retain per-question outcomes, token counts, tool calls, latency, and trace identifiers. An operational failure is an error, not a correct refusal. Rates show counts and Wilson intervals; missing denominators stay null so an empty experiment cannot appear successful.

The red-team harness defines forty attacks across direct injection, poisoned documents, tool misuse, false premises, overreach, and secret leakage. Five fictional documents carry different instruction styles. Defenses include explicit untrusted-document framing, typed tool arguments, instruction-like text quarantine, output checks, and reference validation. Quarantine changes the evidence before it reaches the model, and citation verification uses that delivered text. Generic canaries are permitted in the output guard, but attack-specific success markers are not: a defense that simply recognizes the test answers would contaminate the experiment.

The remaining research work is substantial and visible. Official documents must be collected, labels verified, the test split frozen, thresholds calibrated, and full model experiments performed. Before-and-after findings, latency claims, and judge agreement cannot be inferred from unit tests. Publication also requires an actual repository, a working notebook session, and a recorded demonstration. The repository supplies the machinery for these steps and a dashboard that distinguishes measured results from pending work. Its central design principle is that missing evidence should remain visible, whether the missing evidence concerns a regulatory answer or the project’s own performance.
